# 本地部署 TodoList / 任务成长系统详细开发需求清单

## 1. 产品目标与边界

### 1.1 产品定位

本软件是一款面向个人使用的本地部署任务成长系统，核心能力包括：

- 将长期目标自动拆分为可执行任务树。
- 将每个项目任务继续拆分到最小 20 分钟任务单元。
- 使用代币奖惩、难度等级、完成度、评分和日志复盘形成反馈闭环。
- 使用 Anki 类型记忆卡片支持知识记忆、复习、纠错和导入导出。
- 支持 Windows 桌面端和 Android 移动端。
- 本地优先运行，预留 AI 文本处理 API 接口。

### 1.2 当前版本明确不做

- 暂不实现思维导图编辑。
- 暂不要求多人协作。
- 暂不强制云同步。
- 暂不强制接入具体 AI 服务商。
- 暂不要求公开应用商店发布。

### 1.3 部署原则

系统应支持本地部署和离线使用：

- 用户数据默认保存在本地。
- 核心任务管理、打卡、评分、代币计算、复习提醒等功能应在无网络环境下可用。
- AI 能力通过可配置 API 接口接入；AI 不可用时，系统应保留手动操作流程。
- 数据结构、导入导出和 API 设计应便于后续扩展云同步或第三方 AI 服务。

## 2. 目标平台

### 2.1 Windows 端

Windows 端作为主力规划和复盘端，应重点支持：

- 复杂任务树创建、编辑和调整。
- 批量导入导出数据。
- Markdown 杂记和日志编辑。
- 周志、月志、探索报告查看与导出。
- 知识卡片批量管理。
- 数据库、Excel、APKG 文件导入导出。

### 2.2 Android 端

Android 端作为随身执行端，应重点支持：

- 查看今日任务。
- 确认最小任务完成。
- 开始、暂停、结束计时。
- 任务提醒。
- Anki 类型卡片复习。
- 快速记录杂记。
- 上传图片作为任务评价证据。

## 3. 核心概念定义

### 3.1 项目任务

项目任务是可以继续拆分的任务，例如“完成英语口语课程”“准备考试”“开发一个 App”。

项目任务必须满足：

- 支持父子层级。
- 可由 AI 自动拆分。
- 可由用户手动修改拆分结果。
- 项目任务本身不直接由用户勾选完成，而是由其子任务完成度自动决定。

### 3.2 最小任务

最小任务是执行单元，默认时长为 20 分钟。

最小任务规则：

- 最小任务由 AI 根据项目目标和用户约束自动生成。
- 用户可以修改最小任务名称、内容、预计时长、分类、难度和截止时间。
- 最小任务可以设置为 20 分钟的整数倍，但推荐 AI 拆分时尽量生成 20 分钟粒度。
- 最小任务的完成状态由用户手动确认。
- 最小任务可以记录实际耗时、完成度、自评、备注、图片和客观评分。

### 3.3 日常任务

日常任务是周期性重复任务，例如每日背单词、每周运动 3 次。

日常任务应支持：

- 每日、每周、每月、自定义周期。
- 频次统计。
- 连续完成天数。
- 自动计算剩余完成时间或剩余完成次数。

### 3.4 记忆卡片

记忆卡片为 Anki 类型卡片，用于知识记忆和间隔复习。

记忆卡片应支持：

- 问答卡。
- 正反面卡。
- 填空卡。
- 选择题卡。
- 单词卡。
- 句子卡。
- 图片卡。
- 音频字段预留。
- 标签、牌组、难度、复习记录和错误记录。

### 3.5 代币

代币是系统内的激励单位，既有奖励也有惩罚。

代币应支持：

- 完成任务奖励。
- 高质量完成奖励。
- 连续完成奖励。
- 延期惩罚。
- 放弃惩罚。
- 低完成度惩罚。
- 兑换自定义奖励。
- 代币流水记录。

## 4. 任务拆分需求

### 4.1 自动拆分总流程

用户创建项目任务时，可以输入：

- 任务标题。
- 任务目标。
- 截止日期。
- 每天或每周可投入时间。
- 任务分类。
- 难度预估。
- 期望产出。
- 约束条件。

系统调用 AI 文本处理接口生成：

- 项目任务摘要。
- 任务树层级。
- 阶段任务。
- 周任务。
- 日任务。
- 最小 20 分钟任务。
- 预计总时长。
- 推荐优先级。
- 推荐难度。
- 风险提示。

用户确认后正式写入任务库。

### 4.2 任务树层级

建议默认层级如下：

| 层级 | 名称 | 时间尺度 | 是否可直接完成 |
| --- | --- | --- | --- |
| L0 | 大目标 | 1 个月以上 | 否 |
| L1 | 项目阶段 | 1-4 周 | 否 |
| L2 | 周任务 / 模块任务 | 1-7 天 | 否 |
| L3 | 日任务 | 1 天 | 可选 |
| L4 | 最小任务 | 20 分钟或其整数倍 | 是 |

### 4.3 最小任务生成规则

AI 自动拆分时应遵循：

- 每个最小任务目标清晰，用户打开后知道马上要做什么。
- 每个最小任务尽量控制在 20 分钟。
- 如果任务天然超过 20 分钟，应拆成多个连续最小任务。
- 每个最小任务应包含验收标准。
- 每个最小任务应包含推荐产出物，例如笔记、截图、代码片段、复述内容。
- 不确定内容应标记为“需用户确认”。

### 4.4 用户修改与重算

用户可以修改 AI 生成的任意任务节点。

修改后系统应自动重算：

- 父任务完成度。
- 剩余预计时间。
- 代币预期奖励。
- 难度综合值。
- 每日任务安排。
- 延期风险。
- 周志和月志统计口径。

## 5. 任务完成度计算

### 5.1 最小任务完成度

最小任务完成度由用户确认：

- 未完成：0%。
- 部分完成：用户手动选择 25%、50%、75% 或自定义百分比。
- 完成：100%。

最小任务完成时应记录：

- 完成状态。
- 实际耗时。
- 自评星级。
- 完成备注。
- 图片附件。
- 客观评分，若适用。

### 5.2 父任务完成度

父任务完成度由子任务加权计算，不建议手动直接填写。

推荐公式：

```text
父任务完成度 = Σ(子任务完成度 × 子任务权重) / Σ(子任务权重)
```

默认权重使用预计分钟数：

```text
父任务完成度 = Σ(子任务完成度 × 子任务预计分钟数) / Σ(子任务预计分钟数)
```

如果子任务没有预计分钟数，则使用默认权重 20。

### 5.3 完成度展示

每个非最小任务应实时显示：

- 总完成度百分比。
- 已完成最小任务数量。
- 总最小任务数量。
- 已投入时间。
- 预计剩余时间。
- 当前延期风险。

## 6. 代币奖惩系统

### 6.1 设计目标

代币系统应做到：

- 规则透明。
- 奖励行动，而不是只奖励结果。
- 鼓励高质量完成。
- 对延期、放弃和虚假高估形成轻度惩罚。
- 不让惩罚过重导致用户放弃使用。

### 6.2 推荐奖励算法

基础奖励：

```text
基础代币 = 预计分钟数 / 20 × 10
```

最终奖励：

```text
奖励代币 = 基础代币 × 难度系数 × 完成度系数 × 质量系数 × 时间效率系数 × 连续加成系数
```

参数建议：

| 参数 | 计算方式 |
| --- | --- |
| 难度系数 | 难度 1-5 分别为 1.0、1.15、1.3、1.5、1.8 |
| 完成度系数 | 完成度百分比，例如 80% 为 0.8 |
| 质量系数 | 0.7 + 综合评分 / 100 × 0.3 |
| 时间效率系数 | min(1.2, max(0.8, 预计分钟数 / 实际分钟数)) |
| 连续加成系数 | 连续完成 3、7、14、30 天分别为 1.05、1.1、1.15、1.2 |

质量综合评分：

```text
综合评分 = 自评星级 / 5 × 40 + 客观评分 × 0.6
```

若无客观评分：

```text
综合评分 = 自评星级 / 5 × 100
```

### 6.3 推荐惩罚算法

延期惩罚：

```text
延期惩罚 = 基础代币 × 延期天数系数 × 任务重要性系数
```

参数建议：

| 参数 | 计算方式 |
| --- | --- |
| 延期天数系数 | min(0.5, 延期天数 × 0.05) |
| 任务重要性系数 | 低 0.5、中 1.0、高 1.5、紧急 2.0 |

放弃惩罚：

```text
放弃惩罚 = 未完成比例 × 基础代币 × 0.5
```

低完成度惩罚：

```text
若任务标记完成但完成度低于 60%，惩罚 = 基础代币 × 0.2
```

### 6.4 惩罚保护机制

为避免挫败感，应设置保护：

- 每日惩罚上限，例如不超过当日已获得代币的 50%。
- 新用户前 7 天不启用强惩罚，只显示提醒。
- 用户可为突发事件申请“豁免”，但需写备注。
- 任务被用户主动调整计划且未到截止日期，不触发延期惩罚。

### 6.5 代币流水

每次代币变化都必须生成流水记录：

- 记录 ID。
- 关联任务 ID。
- 变动类型：奖励、惩罚、兑换、修正、手动调整。
- 变动数量。
- 计算依据。
- 创建时间。
- 是否可撤销。

## 7. AI 文本处理 API 需求条目

### 7.1 API 设计原则

AI 能力仅通过接口调用，不应与核心业务逻辑强耦合。

系统应支持：

- 配置 API Base URL。
- 配置 API Key。
- 配置模型名。
- 配置超时时间。
- 配置是否启用 AI。
- 保存 AI 请求和响应摘要，便于排错。
- AI 调用失败时回退到手动编辑。

### 7.2 明确需要 AI 处理文本的功能

以下功能需要预留 AI 文本处理接口：

| 编号 | 功能 | 输入 | 输出 |
| --- | --- | --- | --- |
| AI-01 | 项目任务自动拆分 | 用户目标、截止日期、可用时间、约束 | 多级任务树、最小 20 分钟任务、预计耗时、验收标准 |
| AI-02 | 任务内容自动修正 | 用户修改后的任务、原任务树 | 受影响节点、重算建议、新任务拆分建议 |
| AI-03 | 任务难度预估 | 任务标题、描述、用户历史数据 | 难度 1-5、理由、风险 |
| AI-04 | 最小任务验收标准生成 | 最小任务描述 | 可检查的完成标准 |
| AI-05 | 每日任务推荐排序 | 待办任务、截止日期、精力偏好、历史完成率 | 今日推荐任务列表和排序理由 |
| AI-06 | 日志自动生成 | 当日任务、评分、备注、杂记 | 日志 Markdown |
| AI-07 | 周志自动生成 | 本周任务统计、日志、杂记 | 周志 Markdown、优缺点、改进方向 |
| AI-08 | 月志自动生成 | 月度任务统计、周志、目标进展 | 月志 Markdown、趋势总结、下月建议 |
| AI-09 | 知识卡片生成 | 文本、笔记、单词表、句子 | Anki 类型卡片草稿 |
| AI-10 | 答题自动纠错 | 题目、标准答案、用户答案 | 正误、错误点、纠正建议、相似度评分 |
| AI-11 | 错题原因总结 | 错题记录、用户答案历史 | 错误类型、薄弱点、复习建议 |
| AI-12 | 探索记录聚合 | 零散任务、杂记、标签 | 可能的大主题、项目建议、任务聚类 |
| AI-13 | 探索报告生成 | 时间轴、任务点、杂记、产出 | 探索报告 Markdown |
| AI-14 | 任务评价辅助 | 用户备注、图片说明文本、客观数据 | 客观评价建议、质量评分建议 |
| AI-15 | Markdown 摘要和标签生成 | 杂记正文 | 摘要、标签、关联任务建议 |

### 7.3 AI 输出格式要求

AI 返回结果应尽量使用 JSON，便于系统解析。

示例：

```json
{
  "title": "完成英语口语课程",
  "estimatedMinutes": 2400,
  "difficulty": 3,
  "children": [
    {
      "title": "第 1 周：完成基础发音",
      "estimatedMinutes": 400,
      "children": [
        {
          "title": "练习元音发音 20 分钟",
          "estimatedMinutes": 20,
          "acceptanceCriteria": ["完成跟读", "录音一次", "标记不熟音节"]
        }
      ]
    }
  ]
}
```

### 7.4 AI 安全与可控要求

- AI 输出必须进入草稿状态，用户确认后才写入正式任务。
- AI 不得自动删除用户已有任务。
- AI 修改建议应显示差异。
- 用户可以关闭 AI 功能。
- 用户可以选择是否把隐私内容发送给 AI。
- 本地部署场景应支持接入本地大模型服务。

## 8. Anki 类型记忆卡片需求

### 8.1 牌组管理

应支持：

- 创建牌组。
- 编辑牌组。
- 删除牌组。
- 牌组嵌套。
- 牌组标签。
- 每日新卡数量限制。
- 每日复习数量限制。

### 8.2 卡片字段

基础字段：

- 卡片 ID。
- 牌组 ID。
- 正面。
- 背面。
- 题型。
- 标签。
- 难度。
- 记忆值。
- 复习次数。
- 错误次数。
- 下次复习时间。
- 最近复习时间。
- 状态：新卡、学习中、复习中、常驻抽查、暂停。

扩展字段：

- 例句。
- 解析。
- 图片附件。
- 音频附件路径。
- 来源。
- 自定义字段。

### 8.3 复习算法

建议第一版使用固定间隔 + 表现修正：

| 成功复习次数 | 推荐下次间隔 |
| --- | --- |
| 0 | 当天 |
| 1 | 1 天后 |
| 2 | 3 天后 |
| 3 | 7 天后 |
| 4 | 15 天后 |
| 5 | 30 天后 |
| 6 | 60 天后 |
| 7+ | 进入常驻抽查 |

答题表现修正：

- 答错：复习次数不增加，记忆值下降，次日或当天再次出现。
- 模糊正确：间隔按 50% 计算。
- 正确：进入下一间隔。
- 非常熟练：间隔可乘以 1.3。

### 8.4 常驻抽查

复习成功至少 7 次后进入常驻抽查池：

- 默认每 15-30 天随机抽查。
- 抽查答对则维持常驻。
- 抽查答错则降级为复习中。
- 常驻抽查卡片仍可被搜索、编辑和导出。

### 8.5 导入导出

必须支持：

- 数据库导入导出。
- Excel 导入导出。
- APKG 导入导出。
- CSV 可作为备选格式。
- Markdown 导出可作为阅读备份。

#### 8.5.1 数据库导入导出

应支持本系统数据库备份文件：

- 完整导出所有任务、日志、卡片、附件索引和设置。
- 支持仅导出卡片数据。
- 支持导入时选择覆盖、合并或跳过重复。

#### 8.5.2 Excel 导入导出

Excel 模板建议列：

| deck | front | back | type | tags | example | explanation | difficulty | source |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |

导入时应支持：

- 字段映射。
- 预览前 20 条。
- 错误行提示。
- 重复卡片检测。

#### 8.5.3 APKG 导入导出

APKG 兼容性要求：

- 支持导入 Anki APKG 包中的牌组、笔记、卡片模板和媒体文件。
- 导入后转换为系统内部卡片模型。
- 导出 APKG 时尽量保留牌组、标签、正反面、字段和媒体资源。
- 若遇到不支持的复杂模板，应保留原始字段并提示用户。

## 11. 探索模式需求

### 11.1 探索模式定义

探索模式用于从零散记录、小任务和杂记中逐渐形成大任务。

### 11.2 探索流程

流程：

1. 用户记录小任务、灵感或杂记。
2. 系统按标签、内容和时间聚合。
3. AI 推荐潜在探索主题。
4. 用户确认是否创建探索项目。
5. 探索项目继续拆分为任务树。
6. 完成后生成探索报告。

### 11.3 探索报告

探索报告应包含：

- 探索主题。
- 开始和结束时间。
- 时间轴。
- 关键任务点。

## 16. 验收标准摘要

### 16.1 任务拆分验收

- 用户输入一个项目目标后，系统能通过 AI 接口生成多级任务树。
- 任务树最底层任务必须是 20 分钟左右的可执行任务。
- 用户能编辑 AI 生成结果。
- 用户确认后任务正式创建。
- 父任务完成度由子任务自动计算。

### 16.2 代币验收

- 完成最小任务后系统自动计算奖励代币。
- 延期、放弃、低完成度可产生惩罚代币。
- 每笔代币变化都有流水和计算依据。
- 用户能查看代币余额和历史记录。

### 16.3 记忆卡片验收

- 用户能创建 Anki 类型卡片和牌组。
- 用户能进行复习并记录正误。
- 系统能按复习次数安排下次复习。
- 7 次成功复习后进入常驻抽查。
- 支持 Excel 和 APKG 导入导出。

### 16.4 本地部署验收

- 无网络时可使用核心功能。
- 用户数据保存在本地。
- AI 接口不可用时不影响手动任务管理。
- 支持完整备份和恢复。
